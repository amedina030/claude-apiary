# File Storage

Runtime data splits three ways:

- **Per-target state** — `<main-apiary>/.repos/<name>-<uid>/`, one directory per registered repo, holding scribe, compass, researcher, captures, runner and session state. The launcher resolves it once (`git rev-parse --show-toplevel` on the session's cwd → `<main-apiary>/.repos/registry.json` → allocate an id on first use) and exports `APIARY_TARGET_STATE_DIR` for the child process. `core/utils/state.resolve_state_dir` is the one resolver every tool calls; a breadcrumb at `<target>/.apiary/pointer` lets passive consumers (the GUI) reverse-resolve without re-running the registry.
- **Per-repo install files** — `<repo>/.claude/`, holding the launcher, the pins, the copied slash commands, the flags and the hook log. Git-ignored.
- **Apiary-repo files that are not state** — source, `profiles/`, `context-rules/`, `compass/dimensions.json`, and the budgeter's own log.

**Apiary writes nothing under `~/.claude/`.** Claude Code itself keeps its session transcripts there (`~/.claude/projects/<cwd-key>/*.jsonl`); apiary only ever *reads* them — see [Transcripts](#transcripts).

Spec: scribe note `C-2026-46`. Resolver: `core/utils/state.py`.

## Scribe data

Folder-per-type under `<state-dir>/scribe/`, each note's body as `<seq>.md`
with a sibling `index.jsonl` for fast listing.

| Path | Description |
|------|-------------|
| `scribe/<folder>/<year>/<seq>.md` | Note body. `<folder>` is `todos`, `handoffs`, `decisions`, `wishlists`, `blockers`, `references`, `context`, `general`, or `learnings` (`scribe/store.py::TYPE_FOLDERS`) |
| `scribe/<folder>/<year>/index.jsonl` | One line per note for fast listing |
| `scribe/<folder>/<year>/next_seq` | Monotonic per-(type, year) sequence counter |
| `scribe/<folder>/<year>/archive/` | Archived bodies + their own `index.jsonl` — **inside** the year folder, not beside it |
| `scribe/templates/<type>.md` | Per-type note templates the `add` gate checks required sections against |
| `scribe/memory/MEMORY.md` | One-line index of permanent memory entries; loaded into startup context |
| `scribe/memory/<topic>.md` | One memory entry per file, kebab-case slug |
| `scribe/backups/<YYYY-MM-DD>/` | Dated `index.jsonl` snapshots from `notes.py backup` |

Retention (what auto-archives and when) is a per-type rule set in
`scribe/policy.py` — the table lives in [`scribe/CLAUDE.md`](../../scribe/CLAUDE.md#retention-what-auto-archives-and-when)
and is generated from those constants. It is **not** a flat 30 days.

`scribe.paths.scribe_state_dir()` delegates to `core.utils.state.resolve_state_dir`, which is where the precedence lives: `$APIARY_TARGET_STATE_DIR/scribe` when the launcher set it, then the repo's pin files, then the legacy `.apiary/pointer` breadcrumb, then `<git-root>/.apiary/scribe/` for a target that was never re-bootstrapped. Outside a git repo it returns `None` rather than guessing.

## Runner data

All runner artifacts live under `<state-dir>/runner/` (see the path table) and
are keyed by the UUID minted at intake creation. Nothing under `runner/` in the
checkout is state — `runner/config.json` is source.

The one exception is `<target-repo>/.runner-worktrees/`: a git worktree has to
sit next to the repo it is cut from, so it cannot live in the state dir. It is
covered by the target repo's `.gitignore`.

## Compass data

`<state-dir>/compass/`, all git-ignored.

| Path | Description |
|------|-------------|
| `compass/observations/<session_id_short>.json` | Per-session observations written by `/wrapup` capture or `compass/backfill.py` |
| `compass/observations/archive/<iso-year>-<iso-week>/` | Archived observations (moved when active count ≥ 50 **and** age ≥ 90 days) |
| `compass/personality.md` | Synthesized profile, regenerated weekly, injected by the startup hook |
| `compass/corrections.md` | Optional manual high-weight evidence the synthesizer treats above raw observations |
| `compass/evaluate/last.json` | Cached headline from the last `compass/evaluate.py offline` run, read by `apiary doctor compass` |

`compass/dimensions.json`, `compass/label_vocabulary.json` and `compass/config.json` ship in the apiary repo — source, not state. A session's A/B arm is recorded as `compass_arm` in `<state-dir>/sessions/identity-<sid8>.json`, not under `compass/`.

## Budgeter data

| File | Path | Description |
|------|------|-------------|
| Usage log | `<main-apiary>/budgeter/data/usage_log.jsonl` | All token usage entries (git-ignored) |
| Baseline files | `<main-apiary>/budgeter/tmp/<session>_baseline.json` | Per-session token baselines for the PRE-to-PRE delta; removed by the Stop hook at the end of every assistant turn |
| Usage samples | `<main-apiary>/budgeter/data/usage_samples.jsonl` | One line per usage-limit sample: 5-hour and 7-day utilization with their reset times, and the source (`hook` or `gui`). Written by the Stop hook and the GUI at most every `usage_sample_interval_seconds`, read by `budgeter/usage_calibrate.py`; always the main apiary copy, never redirected per project (git-ignored) |

A project with a `.claude/budgeter.json` redirects both to `<project>/.claude/budgeter-log.jsonl` and `<project>/.claude/budgeter-tmp/` (`budgeter.lib.logger.configure_for_project`).

## Researcher and captures data

`<state-dir>/research/` and `<state-dir>/captures/`, all git-ignored.

| Path | Description |
|------|-------------|
| `research/tags.yaml` | Controlled-tag vocabulary. Edited via `researcher/cli.py register-tag` |
| `research/<topic>/<slug>.md` | One finding per file: YAML-subset frontmatter (title, topic, tags, date_created, date_last_verified, sources) then Summary / Context / Findings / Code / Caveats |
| `captures/tags.yaml` | Controlled-tag vocabulary. Edited via `captures/cli.py register-tag` |
| `captures/<topic>/<slug>.<ext>` | The image, extension preserved (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`) |
| `captures/<topic>/<slug>.md` | Sidecar metadata: frontmatter (title, topic, tags, captured_at, image, optional session_id, related_notes, sources) then a free-text body |

`researcher/template.md` ships in the apiary repo — source, not state.

## GUI data

GUI state lives under `<main-apiary>/.apiary/gui/apiary_gui/`. `APIARY_GUI_PROFILE=<name>` re-roots everything to `apiary_gui_<name>/`, isolating a dev build from the packaged one. All of it resolves through `gui/paths.py` (`state_dir()`, `mutex_name()`, `window_title()`).

Resolving `<main-apiary>` depends on the build. A **source** build uses `gui/paths.py`'s grandparent. A **frozen** PyInstaller build cannot trust `__file__` (it points inside `_internal/`, which is wiped on every rebuild), so it walks up from `sys.executable` for the first ancestor containing both `.git` and `gui/`; a build shipped outside any checkout falls back to a per-user data dir (`%LOCALAPPDATA%`, `Application Support`, or `$XDG_DATA_HOME`).

| File | Path (under the profile dir above) | Description |
|------|------|-------------|
| Tab state | `tabs.json` | Open tab cwds + active index, restored on relaunch |
| Sidebar state | `sidebar_state.json` | Per-group collapsed/expanded state |
| Composer state | `composer_state.json` | Chat input height in pixels |
| Theme | `theme.json` | CSS variable values (hot-reloads via watchdog) |
| Launch config | `launch.json` | Claude Code spawn args + cwd + feature flags (schema in [config files](config-files.md)) |
| Captures | `captures/<ts>-<label>.bin` | Raw pty-output captures, only when `APIARY_GUI_CAPTURE_LABEL` is set |
| File references | `file_refs/<session_id>.json` | Files staged for the composer — path, name, type, size, added-at, `owned`. **Scoped per tab**, so staged files never attach to another tab's message. Dragged files are references; pasted clipboard images are materialised into an owned temp file. Wiped on GUI startup (`FileRefs.wipe_all`); a tab's scope is removed when it closes |
| Pasted images | `pasted/<session_id>/<id>.<ext>` | The owned copies behind `owned` file-reference entries. Deleted on remove/clear and tab close; the whole tree is wiped on GUI startup |
| Permission-MCP config | `permission_mcp_config.json` | `--mcp-config` file handed to claude when `APIARY_PERMISSION_MCP=1`. Rewritten each session start |
| Permission-MCP log | `permission_mcp.log` | START/REQUEST/DECISION/EXIT events from the permission-prompt MCP stdio server |

`theme.json`, `launch.json` and the directory itself are auto-created on first run. PyInstaller build outputs (`dist/apiary-gui/`, `build/`) live at the repo root and are git-ignored.

## Bootstrap state

`apiary install` writes its provenance record at `<state-dir>/bootstrap_state.json`. A pre-migration install that left the file at `<target>/.apiary/bootstrap_state.json` is read once as a fallback, then only the centralized path is written.

| Field | Description |
|------|-------------|
| `schema_version` | State file schema version (currently 1) |
| `profile` | Profile name applied on the last bootstrap |
| `profiles_applied` | Full extends chain in merge order (parents before children) |
| `profile_content_hashes` | `{name: "sha256:..."}` per applied profile — detects profile drift between runs |
| `applied_apiary_keys` | Top-level keys in `.claude/settings.json` that apiary owns after this bootstrap |
| `last_bootstrap_ts` | ISO-8601 UTC timestamp of the last successful run |

Absent state → bootstrap treats the target as fresh. Present state with drift → diff + prompt unless `--force`. Profile manifests live at `<main-apiary>/profiles/<name>.jsonc`. See [Bootstrapping a repo](../guides/bootstrapping-a-repo.md).

## Transcripts

Claude Code — not apiary — writes session transcripts to `~/.claude/projects/<cwd-key>/<session>.jsonl`, where `<cwd-key>` is the session's absolute cwd with separators replaced (`core/utils/project.py` computes the same key). Apiary reads them: `gui/transcript.py` for the GUI's chat pane, `compass/backfill.py` for historical observations, `budgeter/lib/logger.py` for token counts.

What apiary writes is its own session record, under per-target state:

| File | Path | Description |
|------|------|-------------|
| Session history | `<state-dir>/sessions/history.json` | Ring buffer of the last 10 sessions with role/mission tags and the transcript path |
| Last session | `<state-dir>/sessions/last-session.json` | The most recent entry, read by handoff generation |
| Session identity | `<state-dir>/sessions/identity-<sid8>.json` | `{role, mission, registered, compass_arm}` |
| Hook flags | `<state-dir>/sessions/` | Once-per-session guards (`<sid8>-<name>`), swept by age |

## Installed files (per bootstrapped repo)

| Source | Destination |
|--------|-------------|

| `core/launcher_template.LAUNCHER_PY` | `<repo>/.claude/apiary/launch.py` |

| (runtime, `core/hooks/dispatch.py`) | `<repo>/.claude/apiary/hooks.log` — one line + traceback per hook failure, rotated to `hooks.log.1` at 1 MiB |
| `core/context_rules` rendered zone | `<repo>/CLAUDE.md` (sentinel-bounded) |
