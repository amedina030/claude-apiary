Guidance only — no `required:` sections, so nothing here is enforced.

A good todo is actionable without the session that wrote it:

- **First line = the action**, imperative and specific ("Fix the push gate so it honours .secretsallow"), not a topic ("push gate").
- Name the file, function, or command the work starts from.
- Say what "done" looks like — the test that should pass, the output that should change.
- Link related notes by display ID (e.g. D-2026-4, B-2026-2).
- Tag it with `--tags` when it mirrors an external ticket (`ticket:K-2026-99`).
